## **Задание 1: Параллельное суммирование массива**

**Реализовано:** параллельное вычисление суммы 10 миллионов элементов.  

**Использованные инструменты:**
- RecursiveTask<Long> для задачи с возвращаемым результатом  
- Порог разделения: 100,000 элементов  
- ForkJoinPool.commonPool()  

**Основная логика:**  
Массив рекурсивно делится на две части до достижения порога. Малые части суммируются напрямую, результаты объединяются через `join()`.  

## **Output**

```text
=== Параллельное суммирование массива ===
Размер массива: 10000000
Порог разделения: 100000

Последовательное суммирование:
Результат: 50000005000000
Время выполнения: 18 мс

Параллельное суммирование (Fork/Join):
Результат: 50000005000000
Время выполнения: 63 мс

Ускорение: 0,29х
```

## **Задание 2: Параллельный поиск файлов**
**Реализовано:** поиск всех файлов с расширением `.txt` в тестовой директории.  

**Использованные инструменты:**
- RecursiveAction для задач без возвращаемого результата  
- Потокобезопасная коллекция: Collections.synchronizedList(...)  
- ForkJoinPool.commonPool()  

**Основная логика:**  
Для каждой поддиректории создаётся новая подзадача. Файлы собираются рекурсивно. Результаты сохраняются в синхронизированную коллекцию.

## **Задание 3: Параллельная сортировка слиянием**

**Реализовано:** параллельная сортировка массива из 1 000 000 случайных чисел.  

**Использованные инструменты:**
- RecursiveTask<int[]>
- Порог разделения: 10,000 элементов  
- ForkJoinPool.commonPool()  

**Основная логика:**  
Массив делится на две части рекурсивно. Малые массивы сортируются напрямую через Arrays.sort(). Результаты объединяются методом слияния. Проверка корректности через Arrays.equals()

# **Анализ производительности**
Параллельные вычисления через Fork/Join Framework показывают заметное ускорение на больших объёмах данных, особенно для CPU-интенсивных задач, таких как суммирование и сортировка массивов. Правильный выбор порога разделения (threshold) очень важен, так как слишком маленький порог создаёт слишком много подзадач и может замедлить выполнение, а слишком большой уменьшает эффект параллелизма. Для задач ввода-вывода ускорение зависит от структуры файловой системы и не всегда линейно масштабируется с количеством потоков.

# **Выводы**
Fork/Join Framework эффективно ускоряет задачи, которые можно разделить на независимые подзадачи. Он особенно полезен для больших массивов данных и рекурсивных алгоритмов, где параллельная обработка даёт существенный выигрыш по времени. Использование fork() и join() позволяет организовать параллельную рекурсию, а правильная настройка порога разделения обеспечивает баланс между количеством задач и производительностью. Полученные знания применимы при разработке высокопроизводительных и параллельных приложений.
